Rate Ninja API

The browser uses same-origin session endpoints. Rate data is served from SQLite on the server and is not exposed as a raw database file. Copy-paste requests, with placeholders, are the example blocks in the partner and MCP guide and API-README.md. This page does not contain a key, client secret, token, or password.

Three ways to read rates

AccessCredentialPrices
Same-origin session HTTP-only cookie rate_ninja_session A contract owner sees base contract prices. A customer sees each active linked owner's rates with that customer's margin.

Partner API and POST /mcp OAuth bearer token from an owner or customer approval. Header Authorization: Bearer YOUR_ACCESS_TOKEN. Owners receive base contract prices and predictive estimates. Customers receive their own prices through active links.

Partner list filters are case-insensitive exact matches. page defaults to 1 and pageSize defaults to 50, with ceilings 10000 and 100. Predictive after is required and must be more than 90 days ahead; carrier and originPort are optional. Booking lists take optional status of pending, approved, or declined, newest first. bookings:read does not grant bookings:write. Discovery advertises only profile:read, rates:read, and sailings:read. The booking scopes are not advertised in discovery. A client must request them explicitly, for example with scopes in Cursor's mcp.json auth block, and the client must be allowed them. Approving or declining changes data and is final. The booking body is the customer price and the requester, not the base price. Reading a booking request does not change unread state. Customers can list, read and create their own booking requests. Profile, rate, sailing, and predictive tools stay read-only. MCP protocol versions are 2025-11-25 (default) and 2025-03-26. The demo key is not a bearer token.

Keep SESSION_SECRET and RATE_NINJA_API_KEY out of the browser and source control.

Managed Agent Swarm

Session routes for a premium per-company flag, the company's CloudBBS project, and saved swarm definitions. The CloudBBS credential is write-only: it is stored encrypted and is never returned, logged, or written to an audit row. Reads report hasBbsToken only. The same routes are described in docs/managed-agent-swarm.md.

Customer partner access

Customers use GET /api/partner/v1/me/available-rates (rates:read; MCP rateninja_list_available_rates) for app-grid customer prices through active links. Filters carrier, originPort and destinationPort are case-insensitive exact matches; page and pageSize use the usual bounds. Fields are id, carrier, originPort, destinationPort, inlandDeliveryLocation, commodityType, contractOwner, ownerCompanyName, contractNumber, rate20D, rate40D, rate40HC, rateEffectiveDate, rateExpirationDate, notes and bookable. bookable requires an unexpired rate (blank expiry or today UTC qualifies) and at least one price. Lists return { data, meta } with the allocation notice.

Customers use POST /api/partner/v1/me/booking-requests (bookings:write; MCP rateninja_create_booking_request) with { "rateId", "containerSize", "slots" }; the API returns 201 { data, meta }. A repeat create makes another request; clients should list before retrying. Customers list and read only their company requests with bookings:read through the existing booking routes and tools. Their view never includes the deciding user. Reads leave unread state unchanged; a new request is unread for the owner. Hidden rates and another customer's request ids return the same not_found as missing ids.

Customer tokens never receive base prices, margins or owner company ids. Owner rates, sailings, predictive pricing, sailing date ranges, predictive date ranges and decisions return 403 owner_only to customers. Owners receive 403 customer_only on available-rates and create. MCP calls enforce company type before scopes and arguments; tools/list shows customers profile, the four current-rate reference lookups (rate-date-ranges, origin-ports, destination-ports, contract-owners), available rates, booking list, booking read and booking create. Owner discovery keeps the prior owner tools and adds the six reference lookups. Create annotations are readOnlyHint false, destructiveHint false and idempotentHint false; the tool changes data. The available-rates list is read-only. Company type is live on each call. Scopes remain independently required, and discovery still advertises only the three read scopes. Connected apps lets both supported types list and revoke grants; revoked credentials stop working.
